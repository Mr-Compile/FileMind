# Project Rules

## Source of Truth
The implementation must be audited before making claims about current behavior.

## Rule Authority
Do not invent rules. A rule must be traceable to explicit user direction or an approved repository rules document.

## Fact Labels
Use: `EXISTING`, `MISSING`, `BROKEN`, `INCOMPLETE`, `INCONSISTENT`, `LEGACY`, `PROPOSED`, `UNVERIFIED`.

## Change Discipline
Repair before replacing. Reuse before duplicating. Plan before coding. Approval before implementation. QA before completion. Documentation before final handoff. Logical commits after verified work.
