# AI Implementation Plan

## Phase 0 — Audit
Inspect the existing codebase before coding. Identify current architecture, navigation/router, design system, file-operation services, persistence/state handling, platform abstraction and tests. Do not hallucinate missing modules or replace working systems without evidence.

## Phase 1 — Shared contracts
Define route IDs, status/chip vocabulary, operation lifecycle, help/about content model and platform capability interfaces.

## Phase 2 — Navigation
Repair/extend routing, history restoration, breadcrumbs and Android back behavior.

## Phase 3 — Safe operations
Implement preview, confirmation, progress, result, activity and undo integration around existing file services.

## Phase 4 — Help & About
Implement About FileMind, Getting Started, User Guide, What's New, Troubleshooting, Diagnostics, Feedback, Credits and Licenses.

## Phase 5 — Intelligence UX
Add Why/explanation, confidence and Needs Review behavior without changing underlying classification logic unless required.

## Phase 6 — Platform polish
Windows: shortcuts, command palette, desktop density. Android: touch layouts, permissions/access guidance, responsive presentation.

## Phase 7 — QA
Run cross-platform UX, routing, safety, accessibility, state restoration and regression checks.

## Documentation rule
Keep implementation plans under the project's existing plan folder convention. Update relevant feature/architecture/flow/routing documentation after verified changes. Do not create unnecessary duplicate documentation structures.
